# Tiny Together 🐾

เกมบนเว็บสำหรับเพื่อน 4–16 คน: หมาป่าและสายลับ พร้อมหมู่บ้าน SVG เคลื่อนไหว ภาษาไทย/อังกฤษ แชต บอต และเสียงกดค้างเพื่อพูด

## เริ่มใช้งานเร็วที่สุด

ต้องมี Node.js 22.16 ขึ้นไป และ npm เครื่องที่รันต้องเปิดค้างไว้ระหว่างเล่น

แตกไฟล์ ZIP แล้วเปิดเทอร์มินัลในโฟลเดอร์ `tiny-together`:

```bash
npm ci
npm run build
npm start
```

เปิด **http://localhost:3001** เลือกสัตว์ ใส่ชื่อ แล้วสร้างห้อง ส่งรหัส 6 หลักให้เพื่อนที่เปิดเว็บจากเซิร์ฟเวอร์เดียวกัน เมื่อเปิดเติมบอต คุณคนเดียวก็เริ่มลองเกมได้

ถ้าต้องการแก้โค้ดและดูผลทันที:

```bash
npm run dev
```

เปิด **http://localhost:5173** Vite ส่ง `/socket.io` และ `/api` ไปยัง Node ที่พอร์ต 3001 ให้อัตโนมัติ

**บนโทรศัพท์:** `localhost` หมายถึงโทรศัพท์เครื่องนั้น ไม่ใช่เซิร์ฟเวอร์ของคุณ ต้องใช้ URL ที่ได้หลังติดตั้งบน Render/Railway ไมโครโฟนต้องเปิดเว็บผ่าน HTTPS ส่วน localhost เป็นข้อยกเว้นสำหรับการพัฒนา

## ติดตั้งบน Render

1. นำไฟล์ภายในโฟลเดอร์ `tiny-together` ขึ้น GitHub โดยให้ `package.json`, `server`, `client` อยู่ที่ราก repository ไม่อัปโหลด `node_modules` หรือ `.env`
2. ใน Render สร้าง **New → Web Service** และเลือก repository นี้ หรือสร้าง Blueprint จาก `render.yaml`
3. เลือก Node และตั้ง:
   - Build Command: `npm ci --include=dev && npm run build`
   - Start Command: `npm start`
   - Health Check: `/api/health`
   - Environment: `NODE_VERSION=22.16.0`, `NODE_ENV=production`
4. เลือกแผนที่ต้องการและ Deploy เมื่อสถานะพร้อม เปิด URL HTTPS ที่ Render ให้มา
5. เพื่อนทุกคนเปิด URL เดียวกัน คนแรกสร้างห้อง คนอื่นใส่รหัส

เมื่อใช้ Blueprint จะมี `plan: free` ตามไฟล์ที่แนบให้ บริการฟรีมีเงื่อนไขและอาจพักเมื่อไม่มีการใช้งาน ดูข้อกำหนดล่าสุดในบัญชีผู้ให้บริการ ไม่รับประกันว่าจะเปิดตลอดเวลาหรือใช้ฟรีได้ทุกกรณี

เอกสาร: [Deploy Express](https://render.com/docs/deploy-node-express-app), [แผนฟรี](https://render.com/docs/free), [WebSocket](https://render.com/docs/websocket)

## ติดตั้งบน Railway

1. สร้างโปรเจกต์จาก GitHub repository เดียวกัน
2. `railway.json` ให้ Railway สร้างจาก `Dockerfile` ที่แนบให้
3. เปิด Public Networking และ Generate Domain เพื่อรับ URL HTTPS
4. รอ health check ผ่าน แล้วใช้ URL นั้นเล่นกับเพื่อน
5. ตั้งตัวแปร TURN/LiveKit เฉพาะเมื่อจะใช้ความสามารถเหล่านั้น

ไม่ต้องตั้ง `PORT` เองเมื่อผู้ให้บริการกำหนดให้อยู่แล้ว Railway มีข้อกำหนดเครดิต/แผน/ช่วงทดลองของตนเอง ไม่ใช่คำรับรองโฮสต์ฟรีถาวร

เอกสาร: [Express บน Railway](https://docs.railway.com/guides/express), [Free trial](https://docs.railway.com/pricing/free-trial)

## ระบบเสียง และข้อกำหนดที่ปรับให้ถูกต้อง

`simple-peer` เป็นตัวช่วย WebRTC peer-to-peer ไม่ใช่ SFU การใช้มันเพียงตัวเดียวโดยให้ Node ทำ signaling อย่างเดียวไม่สามารถสร้าง SFU ได้ โปรเจกต์นี้จึงใช้:

- **คนจริงไม่เกิน 6 คน:** WebRTC mesh ผ่าน `RTCPeerConnection` มาตรฐาน ส่ง offer/answer/ICE ด้วย Socket.io ไม่ต้องมีบัญชีบริการเสียง
- **คนจริงมากกว่า 6 คน:** LiveKit SFU โดย Node ออก token ให้เฉพาะสมาชิกห้อง ส่วนสื่อเสียงผ่านเซิร์ฟเวอร์ LiveKit แยกต่างหาก ถ้ายังไม่ตั้งค่า UI จะแจ้งและยังเล่นด้วยแชตได้ ไม่มีการแสร้งใช้ mesh แล้วเรียกว่า SFU
- บอตไม่เปิดไมค์และไม่นับเป็นการเชื่อมต่อเสียง
- โหมดเสียงเปลี่ยนเมื่อจำนวนคนจริงข้ามเกณฑ์ ผู้เล่นต้องเปิดเสียงใหม่
- กด **เปิดเสียงสนทนา** และอนุญาตไมค์ครั้งแรก จากนั้นกดปุ่มค้าง หรือกด Space ค้างบนคอมพิวเตอร์
- ปล่อยปุ่ม ออกจากหน้าต่าง ซ่อนหน้าเว็บ เปลี่ยนเฟส หรือหลุดการเชื่อมต่อ จะปิดการส่งเสียง
- ปุ่มลำโพงข้างชื่อปิดเสียงผู้เล่นคนนั้นเฉพาะเครื่องคุณ
- หมาป่าเปิดเสียงเฉพาะกลางวัน; ช่วงลงคะแนน/กลางคืน/นักล่า/รุ่งเช้าเงียบ สายลับเปิดตลอดรอบ
- บางเบราว์เซอร์ต้องแตะปุ่มพูดอีกครั้งเพื่อเริ่มเล่นเสียงที่รับมา

### TURN สำหรับเครือข่ายมือถือที่เชื่อมต่อกันตรง ๆ ไม่ได้

คัดลอก `.env.example` เป็น `.env` ในเครื่องพัฒนา หรือใส่ Environment Variables บนผู้ให้บริการ:

```dotenv
TURN_URL=turn:your-turn-domain.example:3478
TURN_USERNAME=your-issued-username
TURN_CREDENTIAL=your-issued-credential
```

ค่าต้องมาจากผู้ให้บริการ TURN หรือเซิร์ฟเวอร์ของคุณ ไม่ใช่ข้อความตัวอย่างด้านบน TURN ไม่ใช่ SFU และอาจมีค่าใช้จ่าย ค่า TURN ที่แจกให้เบราว์เซอร์มองเห็นได้ตามธรรมชาติของ WebRTC ควรใช้บัญชีจำกัดสิทธิ์/จำกัดโควตา และเปลี่ยน credentials ตามรอบ

### LiveKit สำหรับห้องใหญ่

สร้าง LiveKit project หรือโฮสต์ LiveKit บนโครงสร้างพื้นฐานที่รองรับพอร์ต WebRTC แล้วกำหนด **ฝั่ง server เท่านั้น**:

```dotenv
LIVEKIT_URL=wss://your-livekit-domain.example
LIVEKIT_API_KEY=your-issued-api-key
LIVEKIT_API_SECRET=your-issued-api-secret
```

ใช้ค่าจริงที่บริการออกให้ ห้ามใส่ API secret ในตัวแปรที่ขึ้นต้น `VITE_` และห้าม commit `.env` โค้ดฝั่ง server ใช้ `livekit-server-sdk` ออก token; client โหลด `livekit-client` เฉพาะตอนเปิด SFU

ตัวแอป Node deploy บน Render/Railway ได้ แต่ตัว SFU ต้องโฮสต์ในบริการที่รองรับ UDP และ WebRTC หรือใช้ LiveKit Cloud ไม่ได้รวมเซิร์ฟเวอร์ SFU ฟรีไว้ใน Node ตัวนี้

เอกสาร: [simple-peer](https://github.com/feross/simple-peer), [LiveKit deployment](https://docs.livekit.io/transport/self-hosting/deployment/), [พอร์ต LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/)

## วิธีเล่นและกติกาที่กำหนดไว้

### หมาป่า

- ผู้เล่น 4–16 คน หมาป่า `floor(จำนวนผู้เล่น / 4)` ตัว หมอดู 1 หมอ 1 และนักล่า 1 เมื่อมีตั้งแต่ 6 คน ที่เหลือชาวบ้าน
- สุ่มด้วย random จาก Node crypto บทบาทส่งเฉพาะเจ้าของ หมาป่าเห็นรายชื่อพวกเดียวกัน หมอดูเห็นผลตรวจของตนเอง
- เริ่มกลางวัน 2–10 นาทีตามเจ้าของห้อง ตามด้วยโหวต 35 วินาที เปลี่ยนคะแนนได้ก่อนหมดเวลา ห้ามโหวตตัวเอง
- คะแนนมากที่สุดออก ถ้าเสมอหรือไม่มีคะแนน ไม่มีใครออก
- คืนละ 40 วินาที: หมาป่าเลือกเหยื่อคนละหนึ่งครั้ง รวมเสียงหมาป่าด้วยคะแนนมากสุด ถ้าเสมอสุ่มจากผู้ได้คะแนนสูงสุด
- หมอช่วยตัวเองได้และช่วยคนเดิมซ้ำได้ หมอดูตรวจตัวเองไม่ได้
- นักล่าที่ถูกโหวตหรือถูกฆ่ามี 25 วินาทียิงคนที่ยังมีชีวิตหนึ่งคน หากไม่เลือกจะข้ามการยิง ตรวจแพ้ชนะหลังการยิง
- ไม่มีหมาป่าเหลือ = ชาวบ้านชนะ; หมาป่าเท่ากับหรือมากกว่าคนอื่น = หมาป่าชนะ
- การเดินเข้าบ้านและกลับกองไฟใช้ Framer Motion ท้องฟ้า ดาว โคมไฟ ประตู และไฟใช้ CSS
- ผู้ถูกกำจัดดูเกมต่อได้ แต่พูด โหวต และส่งแชตระหว่างรอบไม่ได้

### สายลับ

- มี 24 สถานที่ แต่ละสถานที่มีอาชีพภาษาไทยและอังกฤษ สายลับสุ่ม 1 คน
- สายลับไม่รับข้อมูลสถานที่หรืออาชีพใน payload; คนอื่นไม่รับชื่อสายลับ
- รอบละ 8 นาที คนที่ถูกถามตอบด้วยเสียงหรือแชต แล้วกดว่าตอบแล้วเพื่อรับตาถามต่อ
- ผู้เล่นถามได้ทีละคำถาม ห้ามถามตัวเอง ถ้าผู้เล่นที่ถึงตาหลุด จะย้ายตาให้คนที่ออนไลน์หลัง 30 วินาที
- ใครก็กล่าวหาได้ มีการกล่าวหาครั้งละหนึ่งรายการ ระยะเวลา 30 วินาที และคนเดิมกล่าวหาได้ทุก 60 วินาที
- ต้องได้เสียงเห็นด้วย **เกินครึ่งของผู้เล่นทั้งหมด** ผู้กล่าวหานับเป็นเสียงเห็นด้วย ผู้ถูกกล่าวหามีสิทธิ์ลงคะแนน
- กล่าวหาถูกสายลับ = คนอื่นชนะ; กล่าวหาผิดแต่ผ่านเสียงข้างมาก = สายลับชนะ; ไม่ถึงเสียงข้างมากให้เล่นต่อ
- สายลับเดาสถานที่ได้ครั้งเดียว ถูกชนะ ผิดแพ้ ถ้าครบ 8 นาทีแล้วยังไม่ถูกจับ สายลับชนะ

## บอตและผู้เล่าเรื่อง

บอตเป็น AI แบบกฎ ไม่ใช้ LLM และไม่ต้องมี API key: โหวตสุ่มโดยเพิ่มน้ำหนักตามคะแนนที่เกิดขึ้น เลือกบทบาทกลางคืนตามสิทธิ์ และถามสายลับจากคลังคำถาม ไม่แอบใช้ข้อมูลบทบาทผู้เล่นอื่นเพื่อตัดสินการโหวต

นกฮูกเป็นผู้ประกาศแบบข้อความและ Web Speech API กดลำโพงบนการ์ดเพื่อเปิดผู้บรรยายพร้อมบรรยากาศกลางคืน ถ้ามีเสียงไทยจะใช้ `th-TH`; ถ้าไม่มีจะพูดข้อความอังกฤษแทน เมื่อปิดเสียงจะหยุด TTS และเสียงบรรยากาศ เสียงกลางคืนสร้างด้วย Web Audio ไม่มีไฟล์เสียงที่ต้องดาวน์โหลดเพิ่ม

## ห้องและการเชื่อมต่อกลับ

- ไม่ต้องสมัครสมาชิก ชื่อรองรับ Unicode และเลือกสัตว์ 8 แบบ
- Session token อยู่ใน `sessionStorage` แยกตามแท็บ; ภาษาและชื่อ/สัตว์ที่เลือกอยู่ใน `localStorage`
- เครือข่ายหลุดแล้วเชื่อมกลับ ใช้ token คืนที่นั่งเดิมได้ตราบใดที่ห้องยังอยู่
- ถ้าเจ้าของห้องหลุด 30 วินาที ย้ายเจ้าของให้คนออนไลน์ ห้องรอยังไม่เริ่มจะเอาคนที่หลุดเกิน 90 วินาทีออก
- ห้องที่ไม่มีคนจริงออนไลน์ 5 นาทีถูกล้าง การกดออกเองระหว่างเกมทำให้เสียสิทธิ์กลับที่นั่งเดิม
- ห้องเก็บใน RAM ไม่ใช่ฐานข้อมูล ถ้าเซิร์ฟเวอร์ restart/deploy/พักแล้วเริ่มใหม่ ห้องเก่าจะหาย ผู้เล่นต้องสร้างใหม่
- ใช้ server instance เดียว หากขยายหลาย instance ต้องเพิ่ม shared room store และ Socket.io adapter ก่อน
- ผู้เล่นในเกมไม่มีอำนาจตัดสินบทบาท คะแนน หรือผลชนะ Server ตรวจคำสั่งและส่งเฉพาะข้อมูลที่ผู้เล่นมีสิทธิ์รับ
- ปุ่มไมค์และการเงียบช่วงกลางคืนบังคับใน client ปกติ ไม่ใช่ระบบต่อต้าน client ดัดแปลงระดับแข่งขัน โดยเฉพาะเสียง P2P

## ตัวแปรอื่น

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ต Node ค่าเริ่มต้น 3001 |
| `CLIENT_ORIGIN` | รายชื่อ origin ที่อนุญาต คั่นด้วย comma เมื่อแยก client/server คนละโดเมน |
| `VITE_SERVER_URL` | URL server สำหรับ build client ที่โฮสต์คนละ origin ต้องตั้งก่อน build |
| `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` | ตัวส่งต่อ WebRTC ในเครือข่ายที่ต้องใช้ relay |
| `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | ระบบเสียง SFU สำหรับห้องใหญ่ |

ค่าเริ่มต้นใช้เว็บกับ Socket.io origin เดียวกัน ไม่ต้องใส่ `CLIENT_ORIGIN` หรือ `VITE_SERVER_URL` และไม่ต้องมีฐานข้อมูล

```bash
npm run build
```

ก่อนเปิดให้กลุ่มใหญ่ใช้ ควรทดลองจริงดังนี้:

1. iPhone/Android ที่ความกว้าง 375px และแท็บเล็ต: สร้าง/เข้าห้อง สลับภาษา เปิดแชต ปัดฉากขึ้นดูเพื่อน ปัดลงดูแชต

3. Wi-Fi กับเครือข่ายมือถือคนละเครือข่าย: ตรวจ TURN
4. 7 คนจริงขึ้นไป: ตั้ง LiveKit แล้วตรวจ SFU แยกจากบอต
5. ปิด/เปิดเครือข่าย: ตรวจว่าได้ที่นั่งและบทบาทเดิม
